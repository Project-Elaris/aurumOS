Build the ISO
=============

Docker build (recommended)
--------------------------

The Docker image provides an Arch Linux environment with Archiso installed.
Docker must be available on the host. The container runs with elevated
privileges because Archiso needs to create and mount filesystem images.

From the repository root, run the build wrapper:

.. code-block:: sh

  ./build.sh

The wrapper builds the Docker image, creates ``output/`` if needed, and starts
the privileged build container.

The ISO and, when generated by Archiso, its package list are placed in the host
``output/`` directory. The ISO filename follows Archiso's profile naming and
includes the ISO name, version, and architecture.

Arch Linux host
---------------

Native builds use the helper scripts in ``installation-scripts/`` and require
an Arch Linux host. The first-build script uses ``/build`` and ``/output`` and
clears the package cache; it is intended to be run as root. The repeat-build
script uses directories under the current user's home directory and may prompt
for ``sudo`` when invoking Archiso.

The scripts display the installed Archiso package version, but do not pin the
build to a particular release. Archiso changes over time, so a newer package
may require updates to the profile. Docker is the preferred path for a clean,
isolated build.

Reproducible version metadata
-----------------------------

``archiso/profiledef.sh`` derives the ISO version and volume label from one UTC
year-month value. Set ``SOURCE_DATE_EPOCH`` to control that timestamp when
building:

.. code-block:: sh

   docker build -t aurumos-iso .
   docker run --rm --privileged -e SOURCE_DATE_EPOCH=1791676800 \
     -v "$(pwd)/output:/output" aurumos-iso

The Docker image must already be built. This fixes release metadata; it does
not make package repositories or the complete ISO bit-for-bit reproducible.
